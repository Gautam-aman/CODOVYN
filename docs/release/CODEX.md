# Isolated Codex sign-in

CODOVYN uses the official **macOS Keychain** backend for its isolated sign-in identity. Coding execution remains blocked: the credential bridge into the restricted coding sandbox is not implemented or verified. Stored authentication does not authorize inference.

1. Install the official CLI separately. CODOVYN pins native ARM64 **0.164.0**, SHA-256 `d8990e3ee7acfbc26f91265b12a1a83f0fee40d0e0f8f1f40a37d4ec21f499cf`. Other hashes fail closed; no automatic install, update or global credential import occurs.
2. Open the disposable Calculator in the copied development app. Trust only that fixture if prompted. Open Chat → Settings → **Sign in to isolated Codex** and confirm the native dialog mentioning strict macOS Keychain storage.
3. Open the official device page from the native dialog and finish authentication in your browser. Do not paste passwords, access tokens, API keys, authentication files or device codes into Chat/issues. Wait for CODOVYN's stored-sign-in confirmation; browser completion alone is not that confirmation.
4. Storage uses `cli_auth_credentials_store="keyring"`, never `auto` or plaintext fallback. The canonical identity lives under this editor profile's private global storage. Normal worker cleanup removes only temporary runtime state. It does not remove the persistent identity or global CLI credentials.
5. **Refresh sign-in status** starts a fresh worker and checks official account/storage metadata. A valid saved account should restore without another browser login. An idle worker can expire while its saved sign-in remains. Keychain/account failures are shown as failures; review normal macOS Keychain permissions or use explicit Sign Out/Reauthentication as appropriate. CODOVYN never unlocks the system Keychain automatically.
6. **Cancel isolated Codex session** stops that worker. **Sign out of isolated Codex**, after native confirmation, removes only CODOVYN's saved identity. No API-key entry is offered in the UI.

The owner validation launcher reuses **Application Support/CODOVYN Owner Validation**. Reopen a validation app through `node scripts/launch-owner-validation.js /disposable/CODOVYN.app /disposable/Calculator` to retain that profile. Arbitrary fresh test/editor profiles intentionally have separate sign-in identities. The owner's installed application is never replaced.

A Signed in label establishes stored account metadata, not model entitlement, quota, cost or successful inference. The Ask validation control is disabled. The previous ephemeral guarded-turn implementation is retained for engineering, but it cannot consume this Keychain identity. No credentials are transferred into the coding process, and no old spending approval is reused. A verified bridge, owner-account restart evidence and fresh exact one-request/native consent are required before any real Ask. Agent editing requires further separate approval and validation.
